# 5,378-chapter TXT manifest scale check

On 2026-09-25, the OWW242 ran an isolated `dev.podjs.tests.manifestscale` package with 5,378 synthetic imported TXT chapters, each containing about 3,000 Chinese characters. This matched the **chapter count** in the main library, but not its content distribution. The fixture used the production PodJS SQL repository, body codec, and Android host services. It generated a complete local sync window; it did not send the full library over Bluetooth.

The first attempt with the old file-backed gzip path exceeded ten minutes before producing a window, so it was stopped. A bounded `file.gzipBytes` host operation now compresses JSON bodies of at most 64 KiB in memory, with the existing file path retained for larger bodies and older hosts. The device codec test checked its gzip bytes against Android `GZIPOutputStream` and rejected oversized input. Redundant SQL reads of absent original-content chunks were also removed, and single-chunk body hashes reuse their chunk hash.

With those changes, the first complete watch run returned 5,378 available full-body manifest entries in 583,947 ms. It made 21,771 SQL queries, 5,378 encodes and 26,891 hashes. A further change batched migration of old reading positions. Its first device run revealed that migration changed the library revision **after** the outer snapshot had captured it; the repository restarted the whole expensive snapshot. That run was stopped, and a regression test now checks that migration finishes before the snapshot revision is captured.

The corrected cold-migration run completed in 557,511 ms with 5,378 available entries, 5,378 encodes, 26,891 hashes and 16,422 SQL queries. That is 5,349 fewer queries and about 26 seconds less wall time than the previous complete run. The difference is one device run per version, not a stable performance benchmark. Both completed runs reported 484,020 compressed body bytes; the repeated-character fixture compresses unusually well. The final guest database had 5,378 articles and 5,378 reading-state rows, `quick_check=ok`, and no foreign-key errors. Snapshots are stored under `.codex-tmp/watch-source-replace-20260925/scale-benchmark/`.

The application suite passed 712 tests and TypeScript type checking. The framework file-codec service test passed; the full framework service file still has an unrelated `system text` test failure caused by missing `react/jsx-dev-runtime`. The independent watch codec instrumentation passed 1/1. The production APK [watchrss-podjs-manifest-scale-fix.apk](../artifacts/watchrss-podjs-manifest-scale-fix.apk) was installed with matching device and local SHA-256 `39c715bc7cff6101dd3e8e8d0e371aac57d381541ae0d10ffc06a3d8ce1fcde6`. It reached a first texture frame. The guest packages were removed, and the production database file SHA-256 was unchanged across installation and launch. It still has 16 channels, 6,006 articles, four TXT-novel channels with 5,378 chapters, seven memo notes, 105 body caches, six saved states and two peers; SQLite checks passed.

The roughly nine-minute first full manifest remains a performance problem. This check does not establish full phone-to-watch transfer time, all real chapter bodies, chapter-list UI parity, or physical interaction parity.
