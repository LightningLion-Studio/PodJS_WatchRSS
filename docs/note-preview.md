# Structured note preview and synchronized images

The note detail screen now consumes structured preview blocks instead of laying out the entire raw Markdown string as one text sequence. The native block parser is ported in `src/notes/preview.ts`: HTML/image discrimination, fenced-code protection, Markdown images, pipe/TSV/aligned tables (including known degraded tables), 1200-character rich-text chunking and source offsets. Thirty cases are captured by executing the verbatim Kotlin parser from `WatchNoteRichText.kt`; the comparison covers block content, alignment, padding, chunk boundaries and offsets.

The UI renders headings, list markers, quotes, literal code rows, independently loaded images and horizontally scrollable tables. Synchronized `assets/...` paths resolve to `notes/assets/...`; thumbnail and tiled full-screen image loaders now accept an existing sandbox file without downloading it. Existing-file sources are excluded from temporary-file cleanup. Image taps use the existing image-preview route. A unit test verifies thumbnail loading performs no HTTP request, releases decoded buffers/textures and retains the source file.

This is an incremental rendering implementation, not complete Compose rich-text parity. Native inline bold/italic/link/subscript/superscript/color spans, exact preset fonts/measurement, table decoration, edit-anchor mapping and full gesture/visual acceptance remain pending. The row layout still uses approximate widths. Large tables are one scroll entry; their rows are not individually virtualized. Existing note data is not rewritten.

The isolated watch fixture `tests/runtime-note-preview` compares the parser against all native cases, receives a deterministic PNG through the production note-asset receiver, loads it through the actual thumbnail and tiled-preview components, checks decoded source dimensions, mounts the production detail component, and verifies source hashes across unmounts. Cleanup removes only its owned note and asset. These callbacks establish decoding/GPU-upload and file ownership behavior; they are not visual acceptance. The previously observed system charging warning has not been dismissed by synthesized input.

Evidence is captured in `artifacts/note-preview-receipt.json`, native capture, unit/typecheck/build logs and `note-preview-guest-kv.json`. Paired-phone end-to-end synchronization, visual comparison and broader migration requirements remain open.
