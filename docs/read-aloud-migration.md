# 朗读迁移记录

本阶段接入原生的文章朗读入口、会话队列和播控页；不表示全部朗读功能已经验收。

## 原生依据

- `Android_WatchRSS/.../data/tts/ReadAloudController.kt`：同频道最多取 48 篇，当前文章不在结果中时前置加入；按 ID 去重并保留当前快照。暂停后重读当前段，调速时重启当前段，关闭自动下一篇后停在本篇结尾。
- `Android_WatchRSS/.../data/tts/engine/LocalTtsEngine.kt`：枚举可见的 TTS 引擎，优先使用已安装的默认引擎；选择离线中文、离线英语语音，再尝试中文／英语语言。初始化最长等待 10 秒。
- `Android_WatchRSS/.../DetailActivity.kt`：点击“大声朗读”启动会话并留在文章页；长按打开播控页，当前文章已有会话时继续使用它。
- `Android_WatchRSS/.../ui/screen/rss/ReadAloudPlaybackScreen.kt`：上一篇、暂停／继续、下一篇、停止、自动下一篇、离散语速档位和返回文章。

## 已接入

`src/reader/speech-segments.ts` 按正文块生成 240 个 UTF-16 单元以内的语音段，保留原始块索引及每个字符的来源位置。空白、标点、标题补句号的规则依据原生实现。图片与视频不转换成待朗读文字。正文长按现按触点与实际行宽、缩放、字距和居中偏移选择字符，再映射回原始 UTF-16 坐标并跳过空白；标题区域长按从头开始。正文外的回退起点按可见文字向后扫描至下一个标点边界。队列保留初次起读位置，错误重试或切回本篇仍使用它；新会话和停止清除旧起点。尚不能标记所有字形和区域的起读位置完全一致，具体边界见下方。硬截断恰好落在代理对中间时，PodJS 保留完整字符；这是相对原生直接 substring 的明确差异。

`src/reader/speech-playback.ts` 管理整个应用的一个会话。停止、暂停、切篇与重试会废弃旧异步结果；新段开始前等待上次停止完成。队列后续文章会重新读取正文，并按频道设置获取原文。选择自动下一篇及播控语速后，停止和开启新会话会保留当前进程内的选择，和原生控制器一致。播控档位为 0.75、0.9、1、1.15、1.3、1.5、1.75、2、2.5、3、3.5、4 倍。

设置页存储的 0.5–2 倍语速与原生播控器自身的离散语速状态是两套状态；本阶段不把它们擅自合并。重新启动应用时播控器回到 1 倍。

`SpeechPlaybackScreen.tsx` 接入真实会话信号，返回文章不停止朗读，停止按钮则停止并返回。文章页启动失败会显示宿主提示。`ScrollEntries` 的长按识别仅在传入回调的阅读器上启用。

应用声明 `media.tts`。宿主新增 `speech.initializeLocal()`，按原生规则选择引擎和语音；后续 speak 传空语言字符串，保留选中的声音。原有显式语言初始化接口继续保留。测试未修改系统默认引擎、系统音量或用户语音数据。

## 朗读高亮与跟随滚动

宿主将生产 `UtteranceProgressListener` 的 start/range/done/stop 事件通过 `speech.progress` 传给应用，保留 utteranceId；已取消或前一段的回调不会更新新段。`ReaderSpeech` 在发出 speak 前订阅，避免丢失提前到达的范围，再在结束时解除订阅。引擎主动停止时会话暂停，不误当成正常完成而跳到下一段。

`SpeechPlayback` 保存当前原文范围。优先使用引擎范围；没有范围时，从实际 start 回调开始，每 900 毫秒按原生混合字符权重和时长模型估计范围，最多推进到 98.5%。初始速度为每秒 3.75 单位；完整段结束后按原生权重平滑校准，暂停或错误不计入样本。一旦收到真实范围，本段不再运行估计定时器。后台计时策略仍待完整验收。

标题高亮将格式化标题映射回原始字符，正文高亮保留 CRLF 与块内 UTF-16 位置；范围计算仅测量当前段涉及的行。临时切换 RSS／原文时，会话记录当前显示模式，以免给另一份内容绘制高亮。背景采用预设强调色，深色 34%、浅色 22%。

当前范围会滚动至视口中央，手动滚动或表冠滚动后等待 3 秒；暂停保留范围但停止跟随。跟随等待的下界为 1 毫秒，以满足宿主定时器契约，避免立即跟随被 0 毫秒请求静默取消。用户物理输入尚未验收。

## 2026-09-13：朗读新会话的静音开播
