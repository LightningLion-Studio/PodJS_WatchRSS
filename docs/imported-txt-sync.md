# Phone-imported TXT to PodJS watch

On 2026-09-25, an isolated physical test connected the installed Android phone companion's production `PhoneCompanionRepository.importLocalContent` and `PhoneBluetoothSyncManager` to the current PodJS watch repository, receiver, and reader service. The phone test used an in-memory Room database and a dedicated temporary cache directory for `FileArticleContentStore`. No test article entered the installed phone or main watch database.

The phone imported `FixtureLong.txt` through the production TXT importer. Its 166,269 UTF-8 bytes were stored as a file-backed phone article. The phone identified an isolated PodJS watch app over the paired public RFCOMM service, checked its device ID, reused the persistent socket, then ran `PHONE_TO_WATCH_REPLACE`. The phone reported one article sent. On the watch, the imported article used the expected `https://watchrss.local/import-content/txt/` identity and an immutable `watchrss-watch-content:` file marker. `ImportedTextStore` read all 11 16-KiB reader chunks back to exactly the original text, including Chinese and emoji. `services.getArticle` exposed an imported-text reader handle and did not expose the file marker as visible body text. The watch completed the applied ACK and peer state; SQLite quick check and foreign-key check passed.

The first phone test attempt stopped before Bluetooth because the custom runner did not expose its test-package Context. The fixture then used a dedicated cache directory and removed it in `finally`; the corrected run passed. The final isolated watch APK SHA-256 was `3438a593adfe7f006e0ff6cf2a53d4354f6a90ee404f154e822224227857671a`; the phone Android test APK SHA-256 was `5ac714d8a8718def29f8f325a087b27481fff8ce7a555186d44d3ec52a29b8b8`. The fixture sources are `tests/runtime-phone-txt-peer` and `Android_WatchRSS_Phone/app/src/androidTest/java/com/lightningstudio/watchrss/phone/connection/bluetooth/PhonePodjsImportedTxtDeviceTest.kt`.

Both test packages were removed and the main watch app restored. Its database still had 16 channels, 6006 articles, 7 memo notes, 105 cached bodies, 6 saved states and 2 peer states; quick check and foreign keys passed. This test proves the repository import, file-backed export, paired transport, watch materialization and reader-service handoff for one TXT. It does not prove the phone file picker and choice UI, visible watch page layout, scrolling/touch anchoring, large-book memory behavior, EPUB/chapter imports, or physical user acceptance.
