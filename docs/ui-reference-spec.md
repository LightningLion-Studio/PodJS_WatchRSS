# Android WatchRSS UI reference for PodJS

This is a source and resource reference for the requested watch surfaces. Values are copied from Android source or the HeyTap widget AAR; no visual values are inferred. Runtime acceptance is still pending target-device screenshots.

## Runtime canvas, density, and type

- Verified physical reference is OPPO watch `OWW242`: **466 × 466 physical px at 320 dpi**, therefore **233 × 233 logical dp** at Android density 2. The evidence is the Android-x2 visual-golden README and the corresponding 466px captures; PodJS must still query runtime display metrics rather than hard-code this for other hardware.
- Android `HomeComposeScreen` provides `Density(2f, baseDensity.fontScale)` around its complete content (`ui/screen/home/HomeComposeScreen.kt`). `FeedScreen` defaults to `densityScale = 2f` and provides `Density(densityScale, baseDensity.fontScale)`. `DetailScreen` provides `Density(2f, baseDensity.fontScale)`.
- `ProfileScreen`, `SavedItemsScreen`, `RssSearchScreen`, and `SettingsScreen` do not install a local density override in their screen source. They consume the activity/runtime density. Keep this distinction; do not globally force 2f for all routes.
- The app font is the bundled `res/font/watch_sans.ttf`, loaded for normal, medium, and semibold weights in `ui/theme/Type.kt`. Material typography sizes are: titleMedium 21sp/26sp; bodyLarge 17sp/21sp; bodyMedium 14sp/17sp; bodySmall 12sp/14sp; labelLarge 14sp/17sp; labelMedium 12sp/14sp; labelSmall 9sp/11sp. Action buttons use 17sp/23sp.
- HeyTap AAR canonical dimensions (`手表适配控件包/heytap-widget-v7.0.18.aar`, `res/values/values.xml`): `hey_content_horizontal_distance=9dp`, `hey_content_horizontal_distance_6_0=14dp`, `hey_distance_2dp=2dp`, `4dp`, `6dp`, `8dp`, `10dp`, `12dp`, `14dp`, `16dp`, `18dp`, `20dp`; base `hey_s_title=16sp`, `hey_s_desription=11sp`, `hey_m_desription=13sp`; home profile avatar `hey_listitem_big_lefticon_height_width=44dp`, avatar border `hey_dotStrokeWidth=0.7dp`, caption `hey_caption=9sp`; HomeDefaultItem right padding `hey_listitem_padding_right=6dp`, base vertical padding `hey_multiple_default_summary_alone_padding_vertical=14.5dp`, summary line slot `hey_listitem_summary_height=19dp`, trailing margin `hey_listitem_widget_margin_left=4dp`, minor trailing offset `hey_listitem_widget_minor_margin_right=-4dp`. For verified round OWW242, `res/values-round-v23/values-round-v23.xml` selects `hey_s_title=17sp`, `hey_m_desription=14sp`, and vertical padding `10dp`; app round resources retain the 44dp avatar and 0.7dp stroke.
- App token mapping (`ui/theme/WatchDesignTokens.kt` and `res/values/dimens.xml`): safe padding 18dp; safe vertical padding 8dp (18dp on round watches); action button 160×48dp; swipe action width 72dp; normal card radius 16dp; button radius 47dp; list icon 30dp; multiple item height 52dp; detail horizontal padding 14dp; detail block spacing 6dp; title line limits 150dp then 190dp. Feed/search/settings title dimensions refer to AAR `hey_s_title` unless their source explicitly selects another token.
- Theme colors (`ui/theme/Color.kt`): Compose primary/brand orange `#FF6026`, dark orange `#ED4735`, light orange `#FF8A3D`; background `#0B1211`, deep background `#070B0B`, surface `#1C1F21`, surface variant `#23272A`, pill `#2A2A2A`, pinned `#333333`, primary text `#F5F5F5`, secondary text `#B6B6B6`, divider `#2C3135`, danger `#E54D4D`, danger container `#612C2C`, reading light background `#F7F4F0`, reading light text `#1C1B1F`. Resource `colors.xml` separately defines legacy `brand_orange=#FF6700` and card `#1C1C1C`; use the referenced source token per component.

## Route architecture

Android uses separate `Activity` routes, with each activity calling `WatchRSSTheme` and hosting one Compose screen. `MainActivity` displays the launch overlay, then routes to OOBE/privacy consent or starts `HomeFeedListActivity`; launcher resume can start Home plus the saved content activity. Home callbacks launch Profile, Notes, recommendations, read-aloud, Add RSS, Feed, and Beian routes. Back is activity-level and guarded by `BaseWatchActivity`; Feed first closes an open swipe row, and Detail saves reading progress through its back handler.

| Surface | Android host and source | Exact structure and route actions |
|---|---|---|
| Home | `HomeFeedListActivity.kt` → `HomeComposeScreen.kt` | Full black root; vertically spaced `LazyColumn`, horizontal safe padding 18dp, top 18dp and bottom 18dp + 6dp. Entries include profile, empty/add prompt, built-in/platform channels, notes placement, read-aloud entry, and RSS channels. Pull-to-refresh, Digital Crown list handler, swipe actions, move-to-top/mark-read, long-press actions. Profile opens `ProfileActivity`; channel opens `FeedActivity`; add opens `AddRssActivity`; notes opens `NotesActivity`; profile and Beian are explicit callbacks. Home density is fixed 2f while preserving system fontScale. OWW242 reference measurements record Notes card 65dp and Profile entry 73dp; verify against target screenshots. |
| Profile | `ProfileActivity.kt` → `ProfileScreen.kt` | Black `WatchSurface`; scroll column with 18dp safe padding and centered `我的` title. Entries are 52dp pills with 47dp radius, `#2A2A2A` fill, 10dp horizontal/8dp vertical padding, 30dp icon, 9dp icon gap: 账号 (conditional), 我的收藏, 稍后再看, 连接手机 (conditional), 设置, 关于, 联系开发者; bottom Beian text. Routes: account → `AccountStatusActivity`, saved/watch-later → `SavedItemsActivity` with save type, phone → `PhoneConnectionActivity`, settings/about/contact/Beian respective activities. Uses runtime density. |
| Feed | `FeedActivity.kt` → `FeedScreen.kt` | `WatchSurface` feed with 18dp safe padding, 8dp image/text spacing, pull refresh, Digital Crown, lazy list and load-more callback. Header click → `ChannelDetailActivity`; item click → `DetailActivity`; long press → `ItemActionsActivity`; favorite/watch-later swipe actions; original-content requests and scroll pause flow back to view model. Feed local density defaults to 2f. |
| Saved items | `SavedItemsActivity.kt` → `SavedItemsScreen.kt` | Black root; lazy list safe padding 18dp on all sides, bottom adds 40dp; header title is 我的收藏 or 稍后再看; hint is local/offline and long-press reorder; sync operation label differs by save type. Empty states are 暂无收藏 / 暂无稍后再看. Supports drag reorder, remove, undo, Digital Crown. Item opens Bilibili detail when link parses as Bili target, otherwise `DetailActivity`; watch-later detail result can auto-remove. Uses runtime density. |
| RSS search | `RssSearchActivity.kt` → `RssSearchScreen.kt` | `WatchSurface` with lazy list, 18dp safe padding, bottom +32dp, 6dp item spacing. Header 搜索 uses `hey_s_title`; then `SearchInputBar`. Blank keyword shows 输入关键词开始搜索; no hits shows 没有找到相关结果; results are cards with title/snippet highlighting, AAR feed title/summary sizes and 16dp card radius. Result click → `DetailActivity`. Activity passes channel ID extra, but screen itself receives keyword/results/update callback. Uses runtime density. |
| Settings | `SettingsActivity.kt` → `SettingsScreenHost.kt` → `SettingsScreen.kt` | Scrollable main/advanced settings route. Source-controlled controls include cache limit/usage, system share, reading font size, media keep-alive/volume/guard/start limit, RSS inline-image prefetch, LLM enable/auto-summary/token usage/prompt preset, OOBE, reader presets, TTS, auto-scroll, remote input, Douyin cookie, performance tools, Beian. Main activity launches Advanced Settings, Reader Preset, TTS, Auto-scroll, Server/remote input, OOBE, performance, LLM preset/usage and Beian activities through callbacks. Uses runtime density; preserve conditional visibility flags (`showPerformanceTools`, detailed TTS, paid AI). |
| Notes | `NotesActivity.kt` → note list/editor UI in the activity | Notes is an activity-level route rather than a `NotesScreen.kt` symbol. It loads folders/notes, supports create via `NoteDetailActivity.createNewIntent`, edit via note ID, long press via `NoteActionsActivity`, image preview via `ImagePreviewActivity`, folder and sort/pin controls, and process-resume handling. Home launches it directly; a long press on the Home notes entry opens note actions. Preserve string/content hashes and conflict metadata from the migration contract. Uses Android activity/runtime density unless the nested content explicitly changes it. |
| Detail | `DetailActivity.kt` → `DetailScreen.kt` | Detail installs 2f density while preserving fontScale. It composes title/metadata/content blocks, original-content toggle and loading notice, offline-media failures/retry, favorite/watch-later state, reading progress, imported-text chunk loading, reader preset, AI summary, read-aloud and auto-scroll actions. Back callback receives item ID and state and owns synchronous reading-progress save. Media routes launch Bili/RSS player; read-aloud routes launch playback/control activities. Detail content uses 14dp horizontal padding, 6dp block spacing, 0dp title safe padding, and title line max widths 150dp/190dp before available-width clamps. |

## Acceptance boundary

The values and route map above are source-derived. PodJS visual parity remains **NOT VERIFIED** until each route is rendered on the target watch at its actual logical dimensions, including round-screen insets, font scale, Digital Crown scrolling, back behavior, empty/loading/error states, and callback destinations. A screenshot or build from another runtime does not close that gate.
