# 阅读器迁移增量

目标仍是原生 `DetailScreen`、`AutoScrollControlScreen` 与阅读器设置的完整行为和画面迁移。本记录只描述已经接入的部分；完整 HTML/媒体正文、原文选择、预设和同步仍未完成。

## 自动滚动与位置

- 阅读器单击正文启停，双击打开自动滚动控制页；使用宿主 `runtime.delay` 区分单击/双击，支持取消待触发的单击。
- 设置默认关闭自动开始，默认每秒 2 行；范围每秒 0.5–10 行、步长 0.5，与原生设置一致。速度以当前正文行高换算，正文底部停止。
- 拖动、惯性/方向键滚动、表冠输入暂停自动滚动。切到其他页面或应用进入后台时挂起推进；恢复后重置时间基准，不补走后台经过的时间。
- 先恢复位置，再应用自动开始。使用独立的 `watchrss.reader.progress.<articleId>` 本地键保存正文 UTF-16 锚点和行内比例；字号或宽度改变后重新定位同一段正文。保留旧记录的归一化进度回退。
- 位置有变化时每秒写回，退出/进入后台时立即写回。不会在恢复完成前用零位置覆盖旧记录。
- 正文换行结果采用响应式缓存，避免每次滚动边界查询都重新测量全文。

原生的 HTML 内容块、图片位置和导入文本字节锚点尚未迁移；这里的纯文本锚点不能当成这些场景的等价实现，也尚未接入跨设备同步。

## 宿主边界修复

Bun 环境有 `setTimeout`，Android 的 PocketJS realm 没有。最初真机单击触发后整帧异常，导致逐帧诊断停在异常前的快照；不是由该快照就能证明“没有点击命中”。阅读器反馈/单击定时现已改为 PodJS `delay`；系统朗读轮询也显式注入该宿主计时服务。纯服务测试覆盖了初始化、语速与宿主延迟参数的传递。
