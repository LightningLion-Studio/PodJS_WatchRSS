# 手机清空手表资料库协议动作

2026-09-24：原生手机端仍会发送 `clearLibrary`，此前 PodJS 返回 `unsupported_action`。现在蓝牙与 IP 的应用动作处理器都会把该请求交给共享库仓储，并在事务提交和文件清理完成后返回原生形状的 `{success:true,action:"clearLibrary"}`。原生手机界面在执行前有两步确认；本次没有通过手机执行该操作。

清空事务删除频道和级联文章、保存状态、附属文章笔记及缓存元数据，同时清除独立的保存/删除同步状态、来源状态、变更日志、peer 游标、身份绑定及本地删除日志。手表设备身份、账号、阅读预设及独立备忘录保留。事务以资料库修订号为条件，避免与并发编辑混合；失败不返回成功，也不触发文件清理。提交后复用现有离线媒体清理与界面刷新路径。行为依据原生 `DefaultRssRepository.clearLibrary()` 与手机端 `ACTION_CLEAR_LIBRARY`，不将其与清空账号或云端资料库混同。

应用 693 项测试与 TypeScript 检查通过。OWW242 独立包使用实际 SQLite 和生产动作处理器，验证清空后的响应、清理回调在提交之后执行、身份/独立备忘录保留，以及故意触发数据库删除失败时不确认成功且保留原记录；`quick_check` 和外键检查通过。独立包已卸载。主包 `artifacts/watchrss-podjs-clear-library-action.apk` 已安装，设备与归档 SHA-256 均为 `eeef0f485bc31ab81c4b0d287a42a5d42cbdb9221ac2b8c1af55441e3dfb3887`；启动后仍有 6006 篇文章、7 条独立备忘录和 105 条正文缓存，主库完整性与外键检查通过。详见 [隔离与部署回执](../artifacts/clear-library-action-receipt.json)。

没有对真实主包资料库执行清空，也没有完成真实手机往返或用户物理验收。随后公共清理路径已加入 B 站／抖音专属缓存桶清理；单元和服务测试覆盖该副作用，真实设备清空后的缓存读回仍未验证，见 [缓存增量](managed-cache.md)。
