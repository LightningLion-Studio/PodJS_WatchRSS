# Library session coordination

`LibrarySyncSession` now sequences a watch-side library exchange: optional cursor request, incoming manifest batches, source merge port, local export window, selected incoming articles, outgoing body requests, response batches, and final acknowledgment. Persistent connections may process another action and finish with `syncSession complete` or `abort`. Each instance owns one connection and closes it; cancellation does not launch another attempt.

The state machine calls `markSuccess` only after a successful applied ACK. A received-only ACK causes a separate wait for applied confirmation. Missing, malformed or failed ACKs leave peer cursors untouched even if individual article commits succeeded. A failed article stage sends a fatal response and ends the connection. Complete-frame writes alone are not sync completion.

`StreamFrameConnection` handles bounded byte fragments with one reader and writer, checks the frame length before allocating its body, and gives the entire frame one deadline. It closes a failed reader. A byte transport must honor its read timeout and resolve writes only after accepting all supplied bytes.

`SqlLibrarySequenceStore` persists peer cursors and change sequence windows. New/old-protocol peers, missing full snapshots, peer cursor disagreement and the seven-day interval select full exports. Missing article state changes are repaired using the same native operation clocks. Ordinary receives do not advance peer cursors. Delta reads are bounded by the captured maximum sequence, preserving later writes for the next exchange. This store is not yet wired to every main-app local mutation.

`library-wire.ts` builds native-shaped manifest and chunk response batches, progress headers and byte estimates. Chunk hashes, body bytes, metadata-only fallback, repeated article chunks and native applied-state statistics are preserved. Progress numbers use short decimals that round-trip to Android Float; legacy Float formatting can use a different equivalent decimal at exponent edges.

The generic SDK `sqlite.transactionChanges` reports SQLite `changes()` after each statement only after successful commit. `SyncArticleReceiver.receiveWithStats` uses the two saved-state upsert counts, so one received article may apply zero, one or two state operations. Existing receive callers retain the void-returning API.

## Verification

`LibrarySessionReferenceTest` runs the unmodified native `WatchBluetoothSyncServer.serveStreams` with an in-memory Room repository injected into the isolated reference application, restoring the original delegate afterward. Thirteen scenarios capture actual response frames and persisted peer state: applied and received/applied ACKs, rejected/missing/wrong ACKs, persistent probe/cursor/session control, fatal article phase, truncated batches, an outgoing saved article, and a nonempty incoming article in watch-to-phone replacement mode.

`LibraryWireReferenceTest` captures nine actual outgoing cases: empty and multiple articles, metadata-only and stale hash fallback, a 450,000-iteration generated body, requested chunk subset, unbatched chunks, and invalid chunk index. Ten native Float values cover ordinary, subnormal and exponent-boundary progress. Sent-at timestamps and localized fatal error wording are excluded from response comparisons; all other fields in the captured successful response frames, including estimated byte counts, are compared directly. Float edge cases compare the reconstructed Float value.

The isolated QuickJS harness additionally uses the real Android SQL/URI/body codec with the production local manifest, article receiver, session and cursor store. Its byte peer fragments an ordinary-RSS metadata-only exchange into reads of at most 17 bytes, requests the body back, and checks SQL before received/applied ACKs. Rollback and truncation must preserve article state and peer cursors. It also compares the 14 earlier native alias merges and their actual applied-state counts.

Final device results and installed package identities are recorded in `artifacts/session-receipt.json`; individual outputs are `reference-library-session-device.json`, `reference-library-wire-device.json`, `session-device-kv.json`, and the `session-*` build/test logs.
