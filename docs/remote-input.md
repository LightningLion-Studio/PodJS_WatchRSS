# 从手机输入

2026-09-14 增量：设置页的「从手机输入」已连接到临时 HTTP 服务与二维码页面；前台蓝牙同步也支持原生 remoteInput 动作。地址交给现有「添加 RSS 地址」确认流程，收到地址本身不会创建订阅。

## 实现范围

HTTP 服务随页面开启，在页面不活动、退出或成功接收一次地址后关闭。退出会取消等待连接和未完成读取。SDK 增加受 net.tcp 能力控制的 Android TCP 监听、接受、关闭和 Wi-Fi IPv4 地址读取，复用现有有界字节流；TCP 与蓝牙共享四个句柄上限。页面保留启动、无 Wi-Fi、二维码与手机下载入口。没有开启设备 Wi-Fi 或授予定位权限。

路由依据现有原生 LocalHttpServer：健康检查、能力信息、下载页与 remoteEnterRSSURL；无关能力返回未找到，原生停用的 LLM 路由保持 410。HTTP 支持原生地址输入形式，限制请求头 16 KiB、请求体 64 KiB，读取总时限 15 秒；响应完成后才交接地址。HTTP 保留原始非空地址，蓝牙按原生规则去除首尾空白。

二维码包含原生中文 Wi-Fi 提示片段，采用白色模块、黑色背景；修正了装饰边框裁掉定位图案的问题。HTTP 未增加原生不存在的配对口令，仅在该页面活动时提供服务。

蓝牙支持持久会话以及旧版 version=1 直接输入。动作完成后向前台界面交接地址，界面忙碌、转场或已有确认时延后处理；取消确认不会调用订阅创建。

## 验证与部署

应用 486 项测试和 TypeScript 检查通过，SDK 服务测试 34 项通过。独立手表包的四项 Android TCP 测试覆盖双向读取、等待超时复用、取消接受、句柄上限和关闭。实际生产 HTTP 页面通过环回请求验证健康／能力查询、非法地址拒绝、中文地址接收、退出取消未完成读取、重开与最终端口释放。

17 组响应与已安装原生参考 APK 的真实处理函数对照，包括状态、类型、内容和回调值。该对照在测试中提供原生 parseBody 输入，并非原生 NanoHTTPD 网络解析器的端到端比较。生产二维码截图由该参考 APK 内的 ZXing 成功解码，得到完整 URL 与中文片段。

真实配对手机通过独立 UUID 连接手表测试包两次：持久会话拒绝空地址并接受中文地址，旧版直接请求接受第二个地址。完整 WatchRSS 根界面两次进入现有确认入口；测试输入服务返回取消，创建调用为零，测试订阅表保持不变。这验证协议和界面交接，未模拟触摸、键盘或滚轮，也未操作原生手机应用界面。

正式包采用 WatchRSS 原标签、版本 0.1.0-dev 和 versionCode 1 覆盖安装，未清除主应用数据。其 DEX 和原生库与两套已测试手表包完全一致。正式包的认证、只读资料查询、Token 记录、阅读预设及七次预览请求回归通过；该回归明确使用 ADB 中继，不作为 Wi-Fi 局域网证明。

安装前后 30 张业务表及 188 个受保护非数据库文件一致，仅 WorkManager 的强制停止时间戳更新。测试应用与中继已清理，原有参考 APK 和手机 APK 哈希不变，主应用恢复前台。

证据收据：`artifacts/remote-input-deployment-receipt.json`。重验脚本：`scripts/verification/collect-remote-input-receipt.py`。收据绑定当前主 APK、源码、协议证明、二维码及无 Wi-Fi 页面截图、数据审计与清理结果。
