# Article phase stream receiver

`ArticleBatchReceiver` accepts article-phase frames after protocol negotiation and manifest selection. Its selected article IDs, hashes, metadata-only modes and requested chunk indexes must come from the watch's manifest coordinator, not from the current peer article frame. It returns the actual committed article count and the peer's requested return bodies only after the last expected frame and all article commits complete. It does not emit a protocol ACK or claim that the rest of a sync session succeeded.

The receiver validates the native batch count/index convention (including the unbatched single-frame form), collects the current article across frame boundaries, rejects noncontiguous repeats and unsolicited bodies/chunks, and serializes commit callbacks. Within a frame, native duplicate-article ordering and last metadata values are retained. Completed preceding articles may remain committed if a later frame fails; the transfer returns no completion receipt in that case. Cancellation cannot undo a transaction already committed, but suppresses completion. Missing requested articles are counted as absent, as native allows, rather than counted as applied.

Cross-frame merging uses the native `LibrarySyncPayload` full merge checks, including body byte count and byte-for-byte duplicate equality. The native streaming server helper omits the byte-count comparison and keeps the first duplicate without checking it; this receiver deliberately uses the stricter full-parser behavior to avoid accepting conflicting data.

`FrameDecoder` now allocates one bounded frame buffer after reading its four-byte header, rather than repeatedly copying the entire incomplete frame. `parseWireJson` retains numeric token provenance so strict metadata distinguishes integers from JSON double/exponent spellings such as `1.0` and `1e0`. The normal JSON tree remains usable by callers. The parser accepts standard JSON, enforces a nesting limit of 128, and rejects invalid UTF-8. Exact integer values beyond JavaScript's safe range are not supported. Encoded pending bodies are capped at 64 MiB; whole-body codec/hydration memory remains an unqualified area.

Java basic Base64 permits unpadded two/three-character tails and noncanonical unused tail bits. Chunk decoding now follows this behavior, rejects whitespace/padding errors, compares SHA text case-sensitively, and compares duplicate decoded bytes instead of encoded strings. Android `JSONObject.optString` treats explicit JSON null as the text `null`; the wire metadata parser follows the observed native behavior.

## Evidence

`ArticleBatchReferenceTest` directly invokes production `LibrarySyncPayload` and `ArticleSyncBody` inside the isolated Android reference package. It captures 19 article parsing cases, 10 batch validation cases and 17 Base64 cases, including numeric JSON types, duplicate conflicts, missing fields and explicit nulls. The fixture contains actual device results and source hashes; `collect-article-batches-device.py` verifies the raw input cases before collecting it. This is Android evidence rather than a JVM JSON substitute.

Bun tests compare all 46 cases and additionally verify arbitrary frame splitting, duplicate-byte equivalence, commit failure, truncation, abort, serialized frame consumption, unsolicited bodies and noncontiguous IDs. `tests/runtime-sync-batches` uses the same test package identity as earlier isolated data tests, but a dedicated batch entry point. It checks the Android corpus in QuickJS, then sends a 260,000-character article and a small article in three frames fragmented into 13-byte reads. Its commit callback calls the production `SyncArticleReceiver`; the large body is read back through the repository. Additional injected database failure and truncation cases must not produce completion.

The phone connection entry point, manifest selection, whole-article deletion, outgoing body responses, peer cursors/change logs and final ACK/session handling remain to be wired. No capability advertising or production main APK changes are implied by this article-phase milestone.
