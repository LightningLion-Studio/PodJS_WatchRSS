# IP synchronization bootstrap

The application can now accept a signed native v2 `ipEndpointDescriptor` in a Bluetooth library probe, authenticate the phone's WebSocket hello acknowledgement and serve the existing library/action session protocol over binary messages. The phone keeps the server role. The watch uses `/sync` and `X-WatchRSS-Protocol: 2`.

Implemented behavior includes native descriptor ordering and compact forms, URL-safe HMAC-SHA256, peer identity and resume-sequence checks, three candidates in descending priority, the 1-second Wi-Fi / 4-second fallback probe deadlines, endpoint cooldown, cancellation when a new bootstrap supersedes a pending probe, persistent and consecutive nonpersistent actions, 10-minute IP request/ACK windows, and transfer/media ownership across backgrounding. Idle background connections stop after 2.5 seconds; completed background transfers have a 30-second grace. The existing Bluetooth listener remains available for bootstrap.

The PodJS Android host adds capability-gated WebSocket negotiation and binary byte streams with bounded queues, cancellation and owned-handle disposal. Local Wi-Fi socket binding follows the native IPv4-prefix selection rule. Other targets do not advertise this new capability.

Validation:

- The unchanged native `IpSyncProtocol.kt` supplies 11 descriptor/hello oracle cases.
- Application tests cover forged signatures, peer/sequence mismatches, cancellation delivery races, descriptor replacement, candidate limits and background grace. The full suite has 432 passing tests; the framework suite has 62.
- Android instrumentation verifies text negotiation, binary fragmentation, timeouts/cancellation and IPv4-prefix matching (3 passing tests on the paired phone).
- `tests/android-ip-peer` and `tests/runtime-ip-peer` exercise a real Bluetooth bootstrap and authenticated WebSocket article exchange between the paired physical devices. The phone independently generates a 180,598-byte gzip body in two chunks, validates the returned chunks and exact text, and checks saved/reading state. The watch checks its durable cursor and export, then removes its isolated article.
- A separate read-only test exercised the deployed main application's public Bluetooth bootstrap and two authenticated IP probes. Its returned identity matches the pre-upgrade database and differs from both the isolated fixture and native application. Main data comparison preserved all 30 table digests and all archived non-database files (172 archived files in total).
- This run explicitly used a temporary ADB TCP relay because the watch had no connected Wi-Fi network. Its `unknownLocal` endpoint is **not wireless LAN, hotspot or Bluetooth-proxy acceptance**. The relay is removed and verified against the prior forwarding lists. The phone instrumentation package is also removed after use.

`artifacts/ip-receipt.json`, produced by `scripts/verification/collect-ip-receipt.py`, binds the tested source and APK hashes to the paired result, type/build/test logs, cleanup and main-library preservation. This receipt must pass before reporting deployment.

Still incomplete or unverified: automatic BLE and mDNS endpoint discovery, network-change-driven discovery/reconnection, actual wireless route selection, normal companion UI/client acceptance, and complete migration/visual/gesture parity. The generic WebSocket host retains binary messages queued before negotiation; native WatchRSS drops binary messages received before the authenticated hello callback. A negotiated binary-message boundary remains a fidelity follow-up. This implementation does not claim complete native IP behavior.

## mDNS discovery increment (2026-09-14)

The SDK now exposes cancellable `discovery.mdns` under `net.discovery` on Android/Wear OS. WatchRSS requests `_watchrss-sync._tcp.`, the `WatchRSS-` name prefix, and the authenticated descriptor's port for a 1500 ms window. Only IPv4 results become priority-300 Wi-Fi route candidates. The controller retains the original signed descriptor, rechecks its expiry after discovery, and authenticates each candidate's HELLO_ACK. Discovery failure retains bootstrap candidates; replacement, background stop, and disposal cancel a pending scan.

Native discovery serializes registration and cancellation, bounds concurrent guest scans and result resolution requests, stops discovery and releases its multicast lock when finished. Android's legacy `resolveService` has no cancellation API; an already submitted resolve may finish after scan closure, and its late result is ignored. BLE descriptor acquisition and network-change subscriptions remain pending.

Evidence: `artifacts/ip-discovery-receipt.json` links source and test hashes. The physical phone passed 8 native tests: four WebSocket tests (including pre-first-text binary dropping) and four mDNS tests. The mDNS tests registered and discovered a private test service, rejected its wrong port, exercised timeout/reuse, and checked cancellation/owner shutdown. Framework: 63 tests. App: 437 tests, including signature gating, discovered-route authentication, expiry during discovery, cancellation, and bootstrap fallback. Typecheck and guest build passed. The temporary phone test package was removed.

This increment has **not** replaced the main watch APK. Phone-local mDNS evidence does **not** establish discovery between phone and watch over Wi-Fi. The previously deployed IP build and its data-preservation receipt remain the deployed baseline; end-to-end wireless acceptance, BLE automatic bootstrap, and visual/interaction acceptance remain open.

## BLE descriptor acquisition increment (2026-09-14)

The SDK now exposes `discovery.status`, `discovery.requestPermission`, and cancellable `discovery.bleReadCharacteristic`. It scans without controller-side UUID filters, validates the advertised UUID, manufacturer marker, and bonded state, then connects over LE and reads the specified GATT characteristic. Scan/read deadlines are independently bounded; cancellation, timeout and service disposal release the scan/GATT ownership. A separate permission request coordinator preserves the existing RFCOMM CONNECT-only behavior. The SDK does not automatically display permission dialogs or enable Bluetooth/location.

WatchRSS's `acquireIpDescriptor` uses the native advertised/service/characteristic UUIDs and `WRS3` marker. Foreground refresh debounces for 350 ms, checks permission, acquires a descriptor, and validates its HMAC before probing. A valid RFCOMM bootstrap cancels an in-flight BLE acquisition; ordinary refresh bursts coalesce. Existing authenticated descriptors remain available after acquisition failure. Network-change subscriptions still remain to be implemented.

The private physical-device fixture passed a bonded phone advertisement/GATT read of 324 exact bytes with matching SHA-256 and a disconnected GATT client. Phone SDK boundary tests cover permission rejection, timeout and cancellation. The first runs exposed watch test-package permission and background-location restrictions, then a missing temporary service in the GATT catalogue. The successful run used a foreground test Activity, verified the private service catalogue, and **did not execute** its conditional cache-refresh fixture branch. No pairing was changed. This proves the SDK's real BLE read; it does not prove a signed descriptor exchange with the normal phone companion or wireless IP transport.

Final checks: 444 app tests, 64 framework tests, 2 native BLE boundary tests, the paired radio read, typecheck and guest build. `artifacts/ip-ble-receipt.json` binds these results and source hashes. The phone fixture was removed; the pre-existing watch test APK was restored by hash, and temporary coarse/fine location grants were revoked. Its data stayed unchanged except WorkManager's force-stop timestamp. The production main app stayed on the deployed mDNS APK throughout BLE testing; its location permissions remain ungranted. The new BLE code has **not** been deployed to that app. BLE permission UI, normal-companion validation, network callbacks, wireless IP and overall migration acceptance remain open.

## Unexpected-disconnection recovery (2026-09-14)

Native `WatchIpSyncManager` schedules refresh on socket closure and failed serving, while treating an explicit `syncSession` completion as a normal shutdown. The PodJS owner now makes the same distinction. Unexpected EOF/failure releases the old route and starts fresh discovery without waiting for a network/lifecycle event. Recovery queues behind a still-settling selection. BLE acquisition retains its 350 ms debounce; hosts using only cached bootstrap endpoints receive the same delay. Backgrounding, disposal and replacement bootstrap cancel pending recovery. Explicit persistent completion does not reconnect.

## Token-usage export (2026-09-14)

The shared RFCOMM/IP application handler now supports `syncLlmTokenUsage`, matching the native response's `success`, `action`, `count` and `records`. Export retains record identity, provider, model, request ID and creation time. Optional token fields follow native normalization: absent/negative values are omitted, nested reasoning falls back to its top-level value, and cached tokens come from the nested prompt details. Export does not synthesize UI totals or treat WatchRSS camel-case aggregate aliases as native fields. Android integer narrowing and floating-point/string conversion are preserved using raw numeric tokens. Limits default to 200; zero returns no rows and negative limits return all rows. Keyset pages retain newest-first order, handle timestamp ties and exclude newly inserted IDs beyond the initial high-water mark. Existing raw data is not rewritten.

The native Kotlin normalizer was executed verbatim on the desktop JVM with the locally installed Android 36 `org.json` sources (only annotations removed), producing 32 comparison cases. These cover optional fields, overflow, long/double distinctions and numeric strings. All 452 app tests and typecheck/build passed; a 305-row SQLite fixture checks pagination, limits, timestamp ties, concurrent inserts and preservation. This is offline native comparison, not nonempty history acceptance on a device.
