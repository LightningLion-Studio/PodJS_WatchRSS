# 日志上传：当前实现

## 用户流程

“联系开发者 → 上传日志”先展示日志范围、可能包含的个人信息、加密、境内存储、保留期限与删除方式。只有点击“同意并开始上传”才会进入一次上传；“暂不上传”返回联系开发者页面。授权随当前路由一次性消费，不写入导航恢复数据；重新打开或恢复旧的上传页不会再次自动上传。

上传前不提供完整日志预览、编辑或逐项移除。若读取到空日志、读取失败或超出大小限制，不会提交请求。上传成功后显示取件码，并把含删除令牌的最小回执保存在系统安全存储。联系开发者页和上传结果页都能打开历史页，确认后向服务端删除。回执过期后由本机清理；服务器的有效期限为24小时，清理任务约每分钟执行一次。

## 客户端协议

- 日志源为 `AppLogger.readLogs()`，运行日志上限为5 MiB；写入时会尝试隐藏密码、Cookie、Authorization、Token 等敏感字段，但不能保证脱敏完全。
- 加密沿用原生格式：UTF-8 → gzip → AES-256-GCM（12-byte IV、128-bit tag、无 AAD），密文布局为 `[IV长度字节][IV][ciphertext || tag]`；32-byte AES 密钥由腕上RSS公钥以 RSA-OAEP-SHA256 封装。
- 上传请求为 `POST https://sly-data-plane.watchrss.cn/functions/v1/log-uploads`，body 是原始密文；密钥封装、字符数和同意版本由请求头传递。客户端不会发送账号 ID。
- 删除请求为 `DELETE /functions/v1/log-uploads/{id}`，使用上传回执中的随机 bearer token。令牌仅在设备安全存储中保留；服务端只存 SHA-256 哈希。
- 网络传输复用现有 HTTP 下载桥接，以私有临时文件读取响应；日志正文、密钥和删除令牌不会写入应用日志。

## 服务端协议与保存

- `POST /functions/v1/log-uploads` 接受最多300 KiB的请求体，并限制密文、RSA 封装、字符数和同意版本；每来源 IP 每小时最多20次。
- 密文上传至配置的私有对象桶（默认 `watchrss-private`）。PostgreSQL `log_uploads` 仅记录对象路径、密文 SHA-256、加密密钥封装、取件码、大小/字符数、同意版本、删除令牌哈希和时间；不记录用户 ID。
- `DELETE /functions/v1/log-uploads/{id}` 校验删除令牌后移除对象和元数据。`GET /internal/admin/log-uploads/{code}` 由管理员鉴权，只返回核验后的密文与加密密钥封装，供获授权且持有配对私钥的维护者离线处理。
- 迁移定义位于同级 `WatchRSS_Backend/supabase/migrations/0090_log_uploads.sql`；启动时后台任务每分钟清理过期记录。Caddy 只把对应管理员路径转发到内部后端。

## 隐私与部署说明

用户提示及服务端隐私政策说明了日志可能包含 RSS 地址、标题、网页地址、设备/系统信息、网络状态和操作上下文；上传源 IP 会用于限流与安全防护。按产品提供方的当前部署说明，日志在中国大陆的自有服务器及对象存储处理，不跨境传输。获授权且持有与内置公钥配对私钥的维护者可以解密日志用于排障和改进服务。

本次验证没有连接生产或测试数据库，也没有向服务器上传真实日志。部署前需先应用 `0038_log_uploads.sql`、部署更新后的后端和 Caddy 配置，再构建发布客户端。私钥不随客户端或本次代码提交。

## 验证

- PodJS：日志上传与宿主加密桥接定向测试通过（9项）；路由恢复单测也确认同意标记不会持久化。
- WatchRSS_Backend：`cargo check --locked --all-targets` 通过；日志上传模块定向单测通过（3项）。现有其他模块仍报告既有 unused/deprecated warnings。
- 全项目 TypeScript 检查目前受当前链接的框架版本阻塞，报错来自原有其他模块缺少框架导出；本次修改文件没有相关类型错误。
